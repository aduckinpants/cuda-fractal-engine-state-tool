# Question-Driven Research Session — Slice 4 Evidence

## Outcome

Slice 4 adds the thin `Research Question…` surface over the canonical services
completed in Slices 1–3. The UI does not parse research responses, validate
overrides, launch proofs, execute sweeps, promote findings, synthesize records,
or record human acceptance itself.

The user-facing route is:

```text
sealed five-question brief
-> exact count and budget review
-> bounded shared-worker execution
-> Answer / Experiments / Visuals / Files
```

## Sealed brief and economic gate

The form captures:

1. the question;
2. the requested focus;
3. current hypotheses or context;
4. fixed-condition notes;
5. the required answer shape.

Executable domains, an optional exact path allowlist, scalar-sweep permission,
zero through two experiment attempts, communication profile, model, reasoning
effort, and a hard dollar budget are explicit controls. Both the legacy V8 POC
panel and the new research panel now default to Luna/high rather than the most
expensive model.

`Run Research` is disabled until `Count & Review Budget` authorizes the exact
current combination of:

```text
Packet ID and manifest hash
sealed research brief
model
reasoning effort
hard budget
```

Changing any form, permission, model, reasoning, or budget value invalidates
that binding and requires another count. The count-only route may upload exact
manifest resources for provider token accounting, but requests no generation
and closes all run-owned provider files.

## Visible authority and results

The exact Packet V8 active Color Pipeline is front-loaded in a prominent strip.
For the exercised ExplainO Transcendental packet it rendered:

```text
Phase Orbit [phase_orbit]
-> Identity [identity]
-> Phase Wheel [phase_wheel_palette]
-> Phase Finish [phase_finish]
```

This same packet-derived context is present in planner, review, and synthesis
contexts. The UI does not reconstruct the chain from raw state.

The result tabs expose:

- deterministic Working Session answer;
- each locked prediction, execution reference, fresh review gate, and
  requested/canonical/emitted value receipt;
- the latest proof-owned candidate PNG or sweep-owned contact sheet;
- every durable run artifact by path.

The status side shows the current research base, attempt count, exact/cumulative
cost events, controller gate, and an allowlisted sanitized event stream.
`Open Run Folder` is available for partial evidence as soon as the durable run
exists; report and visual actions remain separately gated.

## Async and lifecycle ownership

Counting and generation use the application's existing bounded
`AsyncJobRunner`. The exact Packet/finding identity is bound to the request;
stale or cancelled completions cannot update the active session. Finding,
bundle, proof, sweep, legacy automation, and research work are mutually gated.

Reset and close cancel only owned jobs. Durable research runs remain on disk.
The research runner always closes provider-owned uploaded files. The route
cannot accept a candidate or launch a viewer.

## Hostile review

- The first draft permitted generation without an exact prior count gate. The
  final implementation binds count approval to the exact Packet, brief, model,
  effort, and budget and invalidates it on edits.
- UI orchestration constructs canonical services but does not reproduce their
  semantics.
- No provider response text or credential value enters the sanitized event
  view.
- Partial evidence is not mislabeled as a final result.
- Replay proof and automatic research promotion remain distinct from human
  acceptance and launch authority.
- The active Color Pipeline is visible without requiring the user or model to
  infer it from raw state.
- No paid provider count or generation request was made.

No open Slice 4 defect blocks the offline Slice 5 qualification court.

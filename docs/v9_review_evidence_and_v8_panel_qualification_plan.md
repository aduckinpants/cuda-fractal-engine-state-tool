# V9 Review Evidence and V8 Panel Qualification

## Objective

Harden the two defects proven by the first Luna/high assisted qualification cell, then qualify that model profile against the historical Packet V8 panel one fixture at a time.

The campaign is deliberately economic and comparative:

```text
exact Packet V8 authority
+ optional packet-bound enrichment disclosure
+ one bounded author response
-> runtime proof and derived Packet V8
+ exact base/result visual pair
+ controller-owned comparison facts
-> fresh review response
-> automatic gates
-> human comparison with the historical transcript
```

No paid provider call is authorized by this plan. Every live cell requires a count-only receipt, an exact per-cell dollar ceiling, and separate user authorization.

## Proven Pressure Points

The first completed Luna/high assisted run proved that authoring, sparse-override validation, replay proof, finding promotion, fresh-context review, and cleanup operate inside the intended cost boundary. It also exposed two bounded harness defects:

1. The fresh review context received the derived packet and decision ledger, but not an explicit base/result image pair or a controller-owned quantitative comparison.
2. The qualification disclosure gate incorrectly required the derived review disclosure to retain the initial packet's analysis identity.

The engine, Packet V8, override validator, and enrichment providers are not changed by this campaign.

## Contract 1: Paired Review Evidence

The review turn remains a fresh provider conversation and continues to receive the exact derived Packet V8 as current result authority.

It additionally receives:

- the exact manifest-validated `web-agent-frame.png` bytes from the preceding author packet, renamed only for transport as `review-base-web-agent-frame.png`;
- `round-review-comparison.json`, a controller-owned projection comparing the exact transported base and result web derivatives;
- the existing `round-review-ledger.json`;
- the derived packet's exact enrichment disclosure for the configured review profile.

The comparison record contains packet identities, image hashes and dimensions, decoded-pixel comparison statistics, changed paths, and proof identities. It is evidence for review, not state or render authority. Image comparison must reuse the proof service's existing image-fingerprint/comparison owner; this work must not add another decoder or PNG writer.

The review prompt must identify the exact roles of the base image, result packet image, comparison record, and ledger. The original authority packet is not attached again.

## Contract 2: Exact Disclosure Binding

Every `enrichment_disclosure_prepared` event records:

- phase and round;
- configured and effective profile;
- packet ID, manifest SHA-256, and finding ID;
- disclosure ID and analysis ID.

The automatic gate validates each phase independently:

- author disclosure binds to the qualification case's initial packet and expected initial analysis;
- review disclosure binds to the exact derived packet and its own receipted analysis identity;
- blind phases require `analysis_id: null`;
- assisted phases require a non-empty analysis identity;
- the event must agree with the immutable disclosure manifest stored for that phase.

A derived analysis identity is expected to differ when the derived packet changes. That difference is not a gate failure.

## Contract 3: Historical V8 Panel Comparison

The qualification panel contains seven fixtures, A through G, using the exact immutable packet directories and transcripts recorded in `packet_v8_seven_fixture_manual_results.md` and its result notebook.

For every new cell, the ledger records:

- fixture identity and historical transcript path;
- exact packet and model/disclosure profile;
- count-only and actual cost receipts;
- new author, override, proof, derived finding, review, and gate results;
- a human comparison against the historical response;
- whether a useful decision or claim was supported by Packet V8 alone, by newly disclosed enrichment, or by both;
- ambiguity, prediction, camera, observability, and override-quality differences.

These are observational comparisons, not causal A/B claims. A result may demonstrate that new data was used correctly; it cannot prove that the same model would have failed without it unless a separately approved paired test is run.

## Later Boundaries

Run panel cells one at a time. After each cell, compare it with the historical transcript and decide whether to retain the prompt/profile, refine the harness, or move upward on the model ladder. Do not launch the full panel automatically until the spot checks establish a tentative profile.

Bracketed questions are a later bounded question-design slice. They must be represented as explicit fixture prompts with a declared purpose and comparison criterion, not silently folded into the common protocol during this hardening pass.

## Closure Condition

This implementation unit closes when the review context has exact paired evidence, disclosure binding is phase-correct, the seven-fixture comparison ledger is ready, all local rails pass, and Fixture A is count-only ready. Paid qualification and bracketed-question expansion remain separate approval boundaries.

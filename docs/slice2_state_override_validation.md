## Implemented boundary

The new state-override path consumes one exact Packet V6 directory and one exact UTF-8 sparse state-shaped JSON document. It does not import or translate `proposal_v1`, accept agent-supplied identities, lower actions, or use the proposal-era tuple and lane catalogs.

Validation regenerates `state-override-authoring-surface.json` from the exact `state.json`, parameter-surface, and UI-schema bytes copied beside it. The regenerated bytes must equal the bundled index before an override can be accepted. Color Pipeline functions and parameters are enforced directly from the copied UI-Salt contract.

The materializer:

- accepts only `params`, companion-paired `view`, and an existing complete `color_pipeline_draft`;
- rejects duplicates, non-finite values, `null`, unknown or absent paths, read-only domains, and unsupported deployed value types;
- enforces deployed types, ranges, and enum options without a handwritten control registry;
- preserves captured Color Pipeline lane/row topology while permitting contract-valid function and complete parameter-list changes;
- copies exact base bytes for `{}`;
- uses UTF-8 without BOM, two-space indentation, LF newlines, inherited base object order, and one trailing newline for non-empty overrides;
- records exact override hash, base/candidate hashes, requested paths, changed paths, conceptual domains, and companion camera edits;
- writes candidates atomically outside the immutable packet directory.

## Core contracts

### Analysis identity

One immutable analysis identity is derived from exact bytes or canonical JSON
for:

- finding ID;
- Packet V8 packet ID and manifest SHA-256;
- exact state SHA-256;
- exact frame and web-frame hashes;
- exact viewport-facts hash;
- active-model receipt hash;
- runtime executable SHA-256;
- provider ID and version;
- analysis schema version and semantic options.

Disclosure mode is not part of analysis or cache identity. `blind`, `assisted`,
and `break_blind` are separate manifests over immutable outputs.

### Analysis artifacts

```text
findings/<finding-id>/analyses/<analysis-id>/
  binding.json
  common-facts.json
  active-model-receipt.json
  provider-result.json
  engine-evaluation.json
  annotation-set.json
  annotated-web-frame.png
  annotation-render-receipt.json
  summary.md
  receipt.json
```

Artifacts are written lazily and atomically. Existing packets, proofs,
findings, and historical analysis are never rewritten.

### Epistemic status

Every feature or conclusion must declare one of:

```text
exact_packet_fact
exact_symbolic_derivation
numerical_solution_of_exact_derived_equation
engine_authoritative_evaluation
comparison_derived_result
heuristic_detection
interpretation_or_hypothesis
```

Annotation rendering must not upgrade the status of the underlying record.

### Provider registry

Use a static internal registry. Each provider declares:

- provider ID and version;
- supported engine `model_id` values;
- required authority fields;
- explicit support/unavailable decision;
- deterministic feature derivation;
- optional engine-evaluation requests;
- presentation-neutral annotation candidates.

The first production provider is
`polynomial_over_power_escape.v1`, selected from the engine receipt rather than
the UI selector. A synthetic provider test proves slotting without creating a
public plugin API.

### Warp rule

The V1 production provider requires `params.explaino_warp_strength == 0`.
Nonzero warp produces an explicit provider-unavailable result. No nonzero-warp
render, fixture, inversion, or implementation effort belongs in this campaign.

### Annotation separation

`annotation-set.json` contains presentation-neutral records:

- feature identity and kind;
- complex coordinate;
- viewport containment;
- source and web-frame pixel projection;
- derivation/evaluation references;
- epistemic status;
- cautious label text.

`annotation-render-receipt.json` separately binds:

- exact input image hash and dimensions;
- exact output PNG hash and dimensions;
- source-to-output transform;
- annotation IDs and style profile;
- renderer version.

Internal feature IDs do not imply causality. The unannotated image remains
available.

### V9 context and cost

Authoring context:

```text
shared byte-identical foundation
+ one isolated case capsule
+ compact controller-owned round ledger
```

Review context starts fresh and contains only:

```text
refreshed result authority
+ selected experiment
+ locked prediction
+ exact override
+ proof identity/result
+ selected enrichment disclosure
```

Before every provider dispatch, the controller conservatively estimates the
maximum call cost using a versioned user-supplied pricing policy. It rejects a
dispatch whose estimate exceeds the remaining run-dollar budget. Provider
billing remains authoritative. No paid request is authorized in implementation
slices.

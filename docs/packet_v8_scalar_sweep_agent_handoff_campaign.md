## Locked Contracts

### Two mutually exclusive agent outputs

Packet V8 describes two executable authoring modes:

```text
single state
-> one sparse state override rooted at params, view, or color_pipeline_draft

bounded scalar series
-> one Scalar Bracket Sweep V1 plan rooted at
   sweep_version, axis, and member_failure_policy
```

One response never contains both. Ambiguous intent produces one clarification
question and no JSON. Agent-authored Sweep V1 assumes the separate fixed state
override is empty. If a constant secondary mutation is necessary, the agent asks
whether to establish a refreshed base or separately configure the fixed override;
it does not invent a wrapper envelope or smuggle a second axis into the plan.

### Sweep-plan response

After one bracket is selected, the agent returns these concise visible sections:

```text
Selected bracket
Why this axis and values
Expected trend and disconfirmation
Fixed-state and camera policy
Hostile self-review conclusion
```

It then returns exactly one fenced `json` block containing:

```json
{
  "sweep_version": 1,
  "axis": {
    "path": "params.some_direct_numeric_leaf",
    "values": [0.1, 0.2, 0.3]
  },
  "member_failure_policy": "continue_independent"
}
```

The wire-shape example is documentation only and grants no path or value
authority. A real plan must select one structurally admissible direct numeric
`params.*` leaf from the exact packet authoring surface and use 3-9 explicit,
unique, finite, non-base values within its attached limits.

### Structural admissibility is not behavioral authority

A generated Packet V8 section lists structurally admissible scalar axes with
their exact current values, types, and declared limits. This means only that the
existing sweep service can materialize independently validated scalar members.
It does not prove observability, useful spacing, absence of automatic control,
safe nonzero semantics, or visible contribution. The agent must justify the
active observation channel, fixed conditions, automation interactions, expected
information gain, and largest uncertainty. Runtime proof remains behavioral
authority.

Scalar Sweep V1 remains limited to:

- one direct numeric `params.*` axis;
- 3-9 explicit non-base values;
- independent members starting from the same exact packet base;
- `continue_independent` or `stop_on_first_failure`;
- no adaptive recursion within one sweep.

Camera, Color Pipeline arrays, custom roots, nested paths, multiple axes, and
agent calls per member remain outside V1.

### Captured-base reference

Every generated sweep presentation begins with a distinct reference tile:

```text
CURRENT / CAPTURED BASE
<axis path> = <exact serialized current value>
not a sweep member
not newly replay-proven
```

The base image is resolved through the existing finding workspace owner and must
match Packet V8's recorded source-frame SHA-256. It is downsampled once through
the same presentation renderer used for proof-owned candidate images. If the
full source frame cannot be resolved and verified, web-review generation fails
clearly; it does not silently substitute the bounded packet derivative.

An axis value exactly equal by ordinary JSON semantics to the serialized base is
rejected before proof because the captured-base reference already represents it.
No approximate Python equality or engine precision emulation is introduced.
If a distinct request later causes the engine to emit the exact base value, the
member remains unsuccessful but is reported as:

```text
NO_EFFECT_ENGINE_EMITTED_BASE
```

rather than being presented as a CUDA or render failure.

### Three-file web review bundle

The detailed immutable sweep tree remains unchanged. A deterministic derived
transport folder contains exactly:

```text
web-review/
  sweep-review.md
  sweep-evidence.json
  contact-sheet.png
```

Generation is acyclic and deterministic:

```text
contact-sheet.png
-> sweep-evidence.json records its hash and source-artifact hashes
-> sweep-review.md records the evidence and contact-sheet hashes
```

No output self-hashes and no new generation timestamp is added. Repeated
generation from the same immutable sweep is byte-identical.

`sweep-evidence.json` is a derived transport projection, not proof authority. It
consolidates the exact plan, binding, fixed override, aggregate and presentation
receipts, member overrides, and proof references. Every embedded item retains
its original relative path, size, SHA-256, role, and parsed document. Original
files remain authoritative. Recorded machine-local paths may remain source data,
but the readable review never implies that a web agent can open them.

`sweep-review.md` is the compact readable index. It records the source sweep and
packet identities, exact base, fixed conditions, ordered member statuses,
important failures, the contact-sheet/evidence hashes, interpretation guidance,
and `human_acceptance: false`.
